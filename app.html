Everything in the org

          
The manifest above is built from what REST and Tooling can see, and is driven by a date. This one asks the Metadata API instead, which enumerates every type the org supports, including the ones REST cannot reach: sharing rules, layout assignments, translations, custom metadata records, static resources and email templates. You get a zip holding package.xml and an Excel inventory of every component with its last-modified date and author. It makes dozens of calls, so allow a minute on a large org.

Permission plan

        
Salesforce's own converter turns one profile into one permission set, which leaves the same sprawl in a new shape. This works out what the target design should be: the permissions almost every profile grants (one shared set), the profiles that are near-identical (one set between them), and what each profile still needs on its own. It produces a plan and a deployable package, and never writes to the org.
