Install guide · Chrome extension

Org Lens Setup

Inspect and export Salesforce metadata: schema, permissions, automation, code, tests and org health, straight from your browser. Nothing is installed into Salesforce, and no admin setup is required in any org.

~5 minutes Chrome or Edge Your existing session

Part one · Install

  1. 1

    Create a permanent folder

    Chrome loads an unpacked extension from its folder every time it starts, so the files need a home they will keep. Create C:\Tools\OrgLens. Open C:\, right-click → New → Folder → name it Tools, then create OrgLens inside it.

    Don't use Downloads If the folder is later cleaned up or moved, the extension silently stops working.
  2. 2

    Get the files from GitHub

    Everything lives at https://github.com/dineshkothuru/org-lens. Take either route.

    With git, which also makes updates one command: 

    git clone https://github.com/dineshkothuru/org-lens.git C:\Tools\OrgLens

    Without git: on the repo page press Code → Download ZIP, then right-click the download → Extract All… → browse to C:\Tools\OrgLens.

    Check the result: manifest.json, app.html, app.js and an icons folder should sit directly in OrgLens.

    One level too deep? A GitHub ZIP extracts into a folder of its own, so you may end up with OrgLens\org-lens-main\manifest.json. Move the inner files up one level. Chrome needs manifest.json at the folder root.
  3. 3

    Load it in Chrome

    • Open a new tab and go to chrome://extensions.
    • Turn on Developer mode, the toggle sits at the top right.
    • Click Load unpacked and select C:\Tools\OrgLens.
    • The Org Lens card appears, showing its version number.
    Expected Chrome shows a “disable developer mode extensions” reminder after some restarts. It is harmless, dismiss it and carry on.
  4. 4

    Pin the icon

    Click the puzzle-piece icon in the Chrome toolbar, find Org Lens, and click the pin. That is the whole installation, there is nothing to configure in Salesforce.

Part two · Use it

  1. 5

    Log into Salesforce, then click the icon

    Open any org the way you normally do. With that tab active, click the Org Lens icon: it opens in a full tab, already pointed at that org. Logged into several orgs? Pick one from the dropdown, every org your browser has a live session for is listed.

    Org Lens reads the session of the org you choose and calls that org's API directly from your browser. Nothing is stored, and nothing is sent anywhere else.

  2. 6
    New in this version Documentation pack builds one branded document from the org: overview, schema diagram, object catalogue, automation and permissions, as HTML to print or a file Word opens. Sharing model shows the org-wide default on every object, the role hierarchy, and what is actually granting access, including Apex sharing reasons and real share-row counts. Security posture names everyone who can bypass sharing and how they got the permission. Export all metadata asks the Metadata API for every type, zipping package.xml with an inventory of every component. SOQL completes real field names and expands all fields. Code search opens a whole LWC bundle rather than one file of it.

    Find what you need

    Org health lands here

    API calls, storage and async limits, plus a live inventory: objects, fields, Apex, flows, permission sets, reports. Export it as a snapshot, or run the all-in-one org audit. Show all limits opens the full table, every limit the org reports rather than the six headline tiles, with whatever sits closest to its ceiling on top.

    Object browser day to day

    Search an object, click it, read every field, types, required flags, formulas, picklist values. Click a field to see which profiles and permission sets can read or edit it, with missing access flagged in red.

    Documentation pack client deliverable

    One branded document instead of seven exports: org overview and limits, the schema diagram as you arranged it, an object catalogue with every field and what each lookup points at, the automation that fires on those objects, and the permissions picture including who holds the permissions that bypass everything. Put a title, client name and your name on the cover, then download it as HTML to print to PDF, or as a file Word opens directly.

    Schema export documentation

    One workbook: objects, fields, record types, relationships, picklists, validation rules and code inventory.

    Deployment package releases

    Pick a date and get everything changed since then, plus a ready-to-use package.xml for the Salesforce CLI. A second button below it, Export all metadata, asks the Metadata API instead: that enumerates every type the org supports, including sharing rules, layout assignments, translations, custom metadata records and email templates that REST cannot see. It returns a zip holding package.xml plus an Excel inventory of every component with its last-modified date and author, with managed-package components left out unless you ask for them.

    Sharing model architecture

    Which records a user can see, rather than which objects and fields. The org-wide default on every object for internal and external users, how many sharing rules widen each one, the role hierarchy as an indented tree with a headcount per role, and the public groups and queues with their membership. Filter to the objects that are not Private for a review. Rule criteria are not included: those need a metadata retrieve. A third block shows what is granting access in practice: custom Apex sharing reasons, restriction and scoping rules, a per-object count of real share rows split by cause (owner, sharing rule, team, manual, or one of your Apex reasons), and the Apex classes that write to a share object. Sharing sets, share groups and implicit sharing are not exposed by any API and are stated as absent.

    Security posture audits

    Who can Modify All Data, View All Data, Author Apex or Manage Users, with the row saying whether it came from their profile or an assigned permission set. Plus the cleanup list, which understands permission set groups: a set granted only inside a group is reported as in use and names the group, group aggregates and muting sets are left out, and any group still waiting to be recalculated is flagged. Then the genuinely dead ones: permission sets with no assignees and profiles with no users. Tick off inactive users to get the stricter read an audit wants.

    Profile & permission set compare audits

    Differences only: object CRUD, field security, system permissions, Apex and tab access. Each side picks its own org and its own name, so this works within one org or across orgs. + Add another org adds a third side or more, which turns the result into a matrix: one row per permission, one column per side, and a column saying whether they all match.

    Schema diagram documentation

    Pick objects and get a proper ERD: layered layout, right-angle routing, crow's-foot cardinality, master-detail solid and lookups dashed, junction objects flagged. Lines arc over each other where they cross, so a relationship can be followed by eye. Drag boxes, undo a move with Ctrl+Z, find an object by name to tint it, hover a box to dim everything unrelated, click + to pull in its neighbours, then export SVG, PNG or PDF with a title block.

    Code search where is this used

    Grep the source of Apex, Visualforce, LWC and Aura for a string, every matching line with its file and line number. Or press List all files to browse everything and click a file to read its full source. Opening one file of an LWC or Aura bundle opens the whole bundle: the js, html, css and js-meta.xml appear as tabs in reading order, with a total line count, because reading one file of a four-file component tells you very little. Search results are clickable: pick a hit and the whole file opens with every matching line marked and the one you clicked scrolled to. LWC and Aura searches skip managed-package sources, which is most of the volume on an org with big packages.

    SOQL query ad hoc

    Run any read-only SELECT against the Data or Tooling API, read the rows here, export them to Excel. It refuses anything that is not a SELECT. Field names complete as you type: it reads the object in your FROM clause and offers its real fields, with types. A suggestion ending in a dot walks the relationship, so Owner. leads straight to the User fields behind it. Ctrl+Space asks for suggestions anywhere. A "* all fields" entry expands every field of that object into the SELECT list, so you never type them out; FIELDS(ALL) is offered beside it for when the 200-row cap is acceptable.

    Setup audit trail who changed what

    Every Setup change since a date, with who made it and in which area. Filter by user or action text, the first place to look when something broke yesterday.

    Tests & coverage before deploying

    Org-wide and per-class Apex coverage, a one-tick filter for classes below 75%, recent test failures, and a popup showing exactly which test classes cover a given class.

    Scheduled & failed jobs morning check

    What is scheduled to run and what failed overnight, scheduled Apex, batch, queueable and future methods, with the actual error message and how far the batch got before it died.

    Record counts sizing

    How many records each object holds, biggest first, with empty objects flagged, useful for migrations, sandbox planning, and spotting objects nobody uses.

    User access access tickets

    Search a person and see what they can actually do, their profile and every assigned permission set merged, with a “granted via” column naming the source of each right. The answer to “why can this user see that?”.

    Permissions matrix security review

    Tick objects and get object CRUD per profile and permission set on screen, plus a workbook with field-level security and a fields × profiles matrix.

    Org compare sandbox vs production

    Row A is the org you are signed into. Pick another org in row B and you get the detailed A vs B diff: objects, fields, validation rules, Apex, LWC, flows, profiles, permission sets, labels, record types and more. Press + Add another org for a third or fourth and it switches to a matrix instead: every component found in any of them, a column per org, and what differs. The two buttons relabel themselves, so you can see which comparison you are about to run.

    Automation debugging

    Everything that fires when a record is saved, for one object or the whole org: Apex triggers with their events, record-triggered flows before and after save, process builders, workflow rules, and OmniStudio.

    Where is it used? before you change it

    Pick any component: field, object, Apex class, LWC, flow, layout, label, and see what references it, so you know what breaks before you touch it. Fields are matched by id, so same-named fields on other objects are not mixed in.

    Field usage cleanup

    How populated each field is, and which fields hold no data and have no metadata references, your genuine deletion candidates.

    Three ways out Every panel can show results on screen, Copy the table straight to your clipboard (it pastes as a real table into Teams, Slack, Jira or Excel), or export a workbook. Start on screen; copy for a quick answer; export when it needs to be a document.
    Queries you run often In the SOQL panel, Save current keeps a query under a name you choose, so next week it is one pick from the dropdown rather than retyping.

If something looks wrong

What you seeWhyFix
“No logged-in Salesforce orgs found” No live Salesforce session in this browser. Log into an org in another tab, then click Refresh org list.
Clicking the icon does nothing Chrome dropped the extension because its folder moved. Re-run Load unpacked against C:\Tools\OrgLens.
Org health is empty, exports still work Your user lacks “View Setup and Configuration”. Expected: everything else is unaffected.
“Session expired” You logged out of Salesforce, so the session died with it. Log back in, then reopen Org Lens.
A panel reports a component type as unavailable That feature isn't enabled in the org (OmniStudio, the beta Dependency API, and so on). Expected: other sections still run and the sheet says what was skipped.
API calls Every panel spends API requests. Most cost a handful; a schema export or diagram costs one describe per object; field usage costs one aggregate per field, so keep that selection small. Org health shows what is left of the daily allowance: press Show all limits and look at Daily Api Requests.
